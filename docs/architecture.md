# Architecture

Gil Sweep is a .NET 10 solution laid out like [XIV Vault](https://github.com/hazeliscoding/xiv-vault):

| Project | What it is |
| --- | --- |
| `src/GilSweep.Core` | Every behavior: the item database, market adapters, the sweep, ranking and scoring, crafting, history, the watchlist and alerts, settings. No UI types. |
| `src/GilSweep.Desktop` | The Avalonia 12 app (`GilSweep.exe`): views, view models (CommunityToolkit.Mvvm), theme, tray, toasts and updates. Presents Core; holds no market logic. |
| `tests/GilSweep.Tests` | xUnit v3. Core and view-model tests, all offline against recorded responses. |
| `tools/GilSweep.Screenshots` | Renders every screen headless from recorded data and a fixed clock. |

## Core

```
Catalog/        items.json, crafts.json, garland-demand.json (embedded); custom items; DemandIndex ("why it sells");
                ItemVerifier (XIVAPI + Garland Tools, for adding an item)
Configuration/  GilSweepSettings (v1-compatible JSON), ConfigStore, SettingsService, LegacyImporter (v1 → v2, once)
Market/         MarketHttp (retries, user-facing errors), Universalis/ and Saddlebag/ adapters, MarketAnalyzer
                (drill-down and selling advice), normalized models (ItemPrices, ItemMarket, MarketSale, TrendSignal)
Sweep/          SweepEngine (the pricing pass), SweepService (runs and archives sweeps), Ranking (v1's rules),
                OpportunityScorer and OpportunityBoard (the score, best farm, available now/soon, farm session)
Crafting/       CraftCalculator (v1's margins), CraftingAdvisor (sell raw or process first)
Time/           EorzeaTime (clock and node windows), NodeWindows (the tray's list)
History/        MarketSnapshotStore (snapshot files), HistoryService (digest, series, backfill), HistoryReport
Watchlist/      WatchEntry, WatchlistService
Alerts/         AlertService (node reminders, spikes, crashes, undercuts) and its log
Platform/       IAppEnvironment (data folder; GIL_SWEEP_HOME), AtomicFile
```

API response shapes stay inside `Market/Universalis`, `Market/Saddlebag` and `ItemVerifier`. The rest of Core and the whole UI use the normalized models. Time comes from `TimeProvider` and folders from `IAppEnvironment`, so every test runs on a fixed clock in a temp folder.

## A sweep

```
SettingsService ──► SweepService.RunAsync
                      │  previous = store.Latest(world)
                      ▼
                    SweepEngine
                      1. Universalis aggregated prices, 100 ids a request:
                         tracked items, then demand consumers, then recipe ingredients (13 requests)
                      2. Saddlebag market share (optional)
                      3. Universalis current listings, 20 ids a request: farmable and watched items (5 requests)
                      4. rows (v1's math and order) + craft margins (v1's two passes) → MarketSnapshot
                      ▼
                    MarketSnapshotStore.Save   snapshots/sweep-<time>-<world>.json
                    retention: all of the last 48 h, newest per day before that, nothing past the limit
                      ▼
AppSession ◄── Completed
  OpportunityBoard.Build(snapshot, trend baseline, settings, now)   rebuilt every second as the clock moves
  AlertService.CheckSweep                                           spikes, crashes, undercuts
```

A sweep fails only if Universalis can't price the tracked items themselves. Recipe chunks, Saddlebag or listings that fail leave a warning on the snapshot and the rest of the sweep stands. A failed sweep keeps the cached snapshot on screen, shows a banner and retries in five minutes.

## Desktop

- `AppSession` is the shared state: the snapshot for the configured world, the trend baseline, the board, sweep progress and errors. It runs the hourly sweep, the retry after a failure and the node-reminder check, driven by `ITicker` (once a second).
- One view model per screen (`SweepViewModel`, `MarketViewModel`, `CraftViewModel`, `WatchlistViewModel`, `HistoryViewModel`, `SettingsViewModel`), plus `MainWindowViewModel` (navigation, clock, connection, offline banner), `OnboardingViewModel` and `UpdatesViewModel`. View models take interfaces only (`IDialogService`, `IShellService`, `IFilePicker`, `INotifier`, `IAppUpdater`, `ITicker`, `IUiThread`); views have no logic in code-behind.
- `Themes/Tokens.axaml` holds the design tokens (the mockup's Quorum colors with a gold accent), `Typography.axaml` the type scale and surfaces, `Controls.axaml` the control themes, `Motion.axaml` all animation. Motion is left out when Windows animations are off.
- Lucide icons are path data (`Controls/LucideIcons.cs`, generated by `scripts/make-lucide-icons.mjs`), drawn by `Controls/Icon.cs`.
- `Services/Tray.cs` is v1's spawn-clock tray; `Services/Notifications.cs` shows Windows toasts by registering Gil Sweep's AppUserModelID under HKCU (removed on uninstall); `Services/Updates.cs` wraps Velopack.
- One copy runs at a time; a second launch brings the first window forward.

## Files

All in `%AppData%\GilSweep` (or `GIL_SWEEP_HOME`):

| File | What |
| --- | --- |
| `config.json` | Settings, watchlist and thresholds. Same names as v1's config for shared keys. |
| `snapshots/sweep-<time>-<world>.json` | One per sweep. v1's format plus `listings` per row and `warnings`. Only the newest keeps `crafts`. |
| `custom-items.json` | Items added in Settings. |
| `history-backfill-<world>.json` | One round of Universalis sale history, so charts have shape on day one (v1's cache). |
| `alerts.json` | The last 50 alerts. |
| `logs/gil-sweep-<date>.log` | Two weeks of logs: item ids, counts, timings, failures. |

Writes go through a temp file and a rename, so a crash never leaves half a file.

## Tests

- **Characterization.** A harness (`legacy/characterize`, removed at cutover; see commit f0be844) ran the v1 TypeScript unchanged against recorded Universalis and Saddlebag responses; `Fixtures/V1/` holds what v1 produced. Core reproduces it exactly: sweep rows and craft margins, ranking for six characters, Eorzea windows to the millisecond, drill-down and selling advice, digest, history, backfill, prune, and the item verifier.
- **Scoring.** With listings, trends and node windows set aside, the ranking is v1's throughput order; the top Miner or Botanist item is v1's top farm.
- **Failure modes.** Universalis down, Saddlebag down, partial chunks, 429 and 504 retries, garbled JSON, cancellation, stale and empty markets.
- **View models.** First run, the Sweep screen and its clock, farm sessions, hourly sweeps, offline and retry, Market, Craft, Watchlist, History export, Settings, updates waiting for a sweep, toasts.
- One explicit test sweeps the live APIs; it never runs by default.

## Release

`.github/workflows/release.yml` runs on a `v*` tag: tests, a self-contained single-file publish, Velopack Setup and update packages (with a delta from the previous Velopack release), a portable zip, `SHA256SUMS`, and a draft GitHub release. Installed copies find updates on GitHub; an update installs only when chosen in Settings and never during a sweep.
